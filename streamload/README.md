# streamload

换场景地图加载：按块流式提交，到货即显示；未到块按实测加载速率推导占位精度（LOD）。
`make test` 跑自检（10 条断言）。

## 模型

- 同一张地图切成 64 块，大小由固定种子 LCG 生成（1500–3499 字节，共 96000 B），三种网络加载的是同一张图。
- 帧步进固定 60fps。最多 16 条并发传输流（连接数上限）；每帧网络泵把当前带宽在在途流间轮询均摊，带 ±15% 抖动；每块有独立起始延迟。
- **stream 模式（新行为）**：块字节到齐的当帧即提交，逐块显示，同帧多块用单调 `commit_seq` 区分先后。
- **atomic 模式（旧行为）**：所有块到齐后一次性整图提交，之前玩家只看到空白地面（已下载未提交的块同样算占位）。

## 占位精度与到货时间的对应（由加载速率推出）

每帧用实际到货字节维护速率 EWMA（`rate_ema`，冷启动先验为标称速率，之后只用实测值）。
因为在途流会均分带宽，单块 ETA 为：

```
eta = 块剩余字节 × 在途流数 / rate_ema + 剩余起始延迟
eta > 3.0s       -> LOD2（最粗占位）
eta > 0.5s       -> LOD1
其余             -> LOD0（最细占位，即将到货）
已提交           -> LOD3 全精度
```

精度不看标称网速，只看实测速率：慢速网下块长期停在 LOD2，快速网从不出现 LOD2。

## 输出指标（三网 × 两指标 = 六数字，stream 模式）

| 网络 | 完整显示 ms | 占位帧数 |
|---|---:|---:|
| slow   | 23767 | 1425 |
| medium |  6017 |  360 |
| fast   |  1533 |   91 |

- `full_display_ms`：完整显示所需时间（最后一块提交的时刻）。
- `placeholder_frames`：占位帧数——画面上存在至少一个非全精度块的帧数。
- 附带 `chunk_placeholder_frames`（各块占位帧数之和）与每级 LOD 的占用帧。
  实测 LOD 分布：slow `lod2=45712 lod1=4274 lod0=754`；medium `lod2=0 lod1=11563 lod0=1264`；fast 全部 `lod0=3105`。

## 整图提交诊断

若三网占位帧数极差小于均值 5%（题面启发式）**或**不同提交时刻数只有 1 个（硬证据），
判定提交是按整张图做的，随即打印每块实际提交时刻（8×8 网格，秒）核对：

- atomic 模式：三网均只有 1 个提交时刻，64 块全部为 23.77s（slow），诊断触发。
- stream 模式：三网均有 64 个不同提交时刻；slow 首块 2.92s、末块 23.77s，跨越 20.85s 渐进显示，诊断不触发。

注意：屏幕级占位帧数在两种模式下都近似等于加载时长（最后一块完成前画面总存在占位），
所以帧数是否接近只是启发式；提交时刻数量才是区分按块/按整图提交的决定性证据。
