# reorder

接收端快照重排缓冲：长度可配置，满时丢弃最旧帧并计数。

`make test` 跑自检，`make report` 跑 3 种丢包率 × 3 次的实验，
`make sweep` 跑窗口/容量扫描，`make verify` 跑性质验证。

## 问题

快照每个 tick 发一次，但网络乱序。若收到即应用，一个晚到但 tick 更小的帧会把
客户端状态覆盖回旧值 —— 表现为物体向后瞬移。乱序本身无法消除，只能在接收端
用时间换顺序。

## 推导：乱序窗口与最大可容忍回退时间

记号：

| 符号 | 含义 |
|---|---|
| `dt` | 快照发送间隔（秒/tick） |
| `D` | 重排窗口，缓冲延迟 **D 个 tick** 后再放出（`hold`） |
| `w` | 一次乱序的跨度：某帧比已经出现过的最大 tick 新值落后 `w` 个 tick |
| `T` | 允许的最大回退时间（秒） |

**1. 回退量。** 乱序跨度 `w` 的帧若被立即应用，位置从 tick `n` 回退到 `n-w`。
物体速度有限时，客户端看到的位移就是 `w` 个 tick 的运动量；以时间计的回退量

```
rewind = w · dt
```

这是*回退时间*，与速度无关：只要 `w·dt > T` 就违反了可容忍上限。

**2. 容忍条件。**

```
w · dt ≤ T        ⟺        w ≤ T / dt
```

**3. 窗口取值。** 缓冲持有 `D` 个 tick 后按 tick 递增放出。一个跨度 `≤ D` 的帧
到达时，水位（已见最大 tick）最多比它新 `D`，所以它一定还没被放出，因此能被
放回正确位置、修好顺序。跨度 `> D` 的帧到达时水位已推进过它的位置，无法回插，
只能丢弃 —— 丢弃的那一帧若应用才是回退超限，所以丢弃正是保护 `T` 的手段。

```
D = floor(T / dt)        且   D·dt ≤ T
```

**4. 容量。** `(newest-D, newest]` 区间内最多有 `D+1` 个不同 tick（含端点），
重度丢包只会让帧变稀疏、不会变多，所以

```
cap ≥ D + 1
```

即可保证窗口内帧不被挤掉；`cap < D+1` 时缓冲会满，此时按“丢最旧”处理并计入
`evicted`，输出仍然单调（不会回退，只是多丢帧）。

**5. 代价。** 每条快照固定多出 `D·dt ≤ T` 的播放延迟。

**数值示例**（本模块 `DT = 50 ms`）：

| `T` | `D = floor(T/dt)` | 实际延迟 | `cap ≥ D+1` |
|---|---|---|---|
| 100 ms | 2 | 100 ms | 3 |
| 250 ms | 5 | 250 ms | 6 |

延迟抖动上限 `JITTER = 5` tick（250 ms）时，`D = 5` 恰好覆盖，丢弃为 0。

**边界。** 回退量按 tick 计而非按量化后的位置差计：`D·dt = T` 时正好到上限，
可以接受；`D·dt > T` 则不可接受。量化误差（`1/pos_scale`）不改变这个结论，
因为它与 tick 无关，且不在单调性判断之内。

## 接口

```c
void reorder_init(Reorder*, int cap, int hold);   /* cap 帧, hold tick */
int  reorder_insert(Reorder*, unsigned tick, float x);
void reorder_flush(Reorder*);                     /* 流结束，放出剩余 */
```

`reorder_insert` 返回 0 表示收下，-1 表示拒收（计入 `late_dropped` 或
`duplicated`）。丢弃计数分三类：`late_dropped`（水位已过、再放就回退）、
`evicted`（缓冲满丢最旧）、`duplicated`（同 tick 重复）。

## 实测

设置：200 个 tick 的快照流，`dt=50 ms`，20 Hz，速度 10 u/s（每 tick 0.5 u），
网络延迟取 `[0, 5)` tick 均匀分布，按到达时间排序后喂给缓冲。丢包率
0%、10%、30%，各跑 3 次（固定种子，可复现）。

`naive` 是收到的帧直接应用时的最大回退；`buffered` 是过缓冲后的最大回退。

### `T = 100 ms`（`D=2`, `cap=3`，窗口小于抖动上限）

| 丢包 | 丢弃帧数（3 次） | naive 最大回退（3 次） | 缓冲后回退 | 最终位置（3 次） |
|---|---|---|---|---|
| 0%  | 12 / 12 / 13 | 200 / 200 / 200 ms | 0 / 0 / 0 | 99.50 / 99.50 / 99.50 |
| 10% | 3 / 11 / 12  | 150 / 200 / 200 ms | 0 / 0 / 0 | 99.50 / 99.50 / 99.50 |
| 30% | 4 / 10 / 2   | 200 / 200 / 150 ms | 0 / 0 / 0 | 98.50 / 99.50 / 99.50 |

窗口只覆盖 100 ms，而抖动可达 250 ms，所以跨度 > 2 tick 的帧被丢弃；丢弃量随
乱序频率而非丢包率变化（丢包打断成对乱序，30% 时反而更少）。

### `T = 250 ms`（`D=5`, `cap=6`，恰好覆盖抖动）

| 丢包 | 丢弃帧数（3 次） | naive 最大回退（3 次） | 缓冲后回退 | 最终位置（3 次） |
|---|---|---|---|---|
| 0%  | 0 / 0 / 0 | 200 / 200 / 200 ms | 0 / 0 / 0 | 99.50 / 99.50 / 99.50 |
| 10% | 0 / 0 / 0 | 150 / 200 / 200 ms | 0 / 0 / 0 | 99.50 / 99.50 / 99.50 |
| 30% | 0 / 0 / 0 | 200 / 200 / 150 ms | 0 / 0 / 0 | 98.50 / 99.50 / 99.50 |

窗口 ≥ 实际最大跨度（3–4 tick）后不再丢帧，只付 250 ms 播放延迟。

### 窗口扫描（丢包 10%，`cap = hold+1`）

```
hold=0  dropped=59   hold=3  dropped=0
hold=1  dropped=18   hold=4  dropped=0
hold=2  dropped=3    hold=5..7 dropped=0
```

丢弃数随 `hold` 增大单调降到 0，拐点在 `hold = max_span`，与推导一致。

### 容量扫描（`hold=4`，无丢包）

```
cap=1 dropped=191   cap=3 dropped=151   cap=5 dropped=0
cap=2 dropped=182
```

`cap < D+1 = 5` 时全部计入 `evicted`；达到 `D+1` 后归零。

### 性质验证

`--verify` 覆盖 5 种丢包率 × 50 个种子 × 所有 `hold`/`cap` 组合：

- 1503067 次插入中，输出序列**始终严格递增**，缓冲后回退恒为 0；
- 54226 次 late drop 全部满足 `tick ≤ last_out` 且 `newest - tick ≥ hold`，
  即“回退会超限”才丢弃；
- 窗口和容量都足够（`hold ≥ max_span` 且 `cap ≥ hold+1`）的 1500 个组合
  丢弃数全为 0。

## 局限

- 只处理乱序，不处理重传/重复包以外的丢失恢复；丢失的 tick 会在输出里留下
  位置跳变（`gaps`），由上层插值或重发补齐。
- `newest` 是水位，若某个 tick 永久丢失且其后续帧提前到达，窗口会照常推进；
  这正是 `hold` 相对水位而非相对“上一个放出帧”定义的原因。
- 输出缓冲 `out[]` 只保留前 4096 帧用于检查，实际使用只看计数。
