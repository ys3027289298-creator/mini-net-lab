# interp

自适应深度的插值缓冲。`make test` 跑自检并打印比对表与延迟/平滑度曲线。

## 为什么按“延迟峰值”定深度，而不是平均抖动

固定深度两头不讨好：浅了，一簇迟到包就卡帧；深了，链路干净时也白等。
常见做法是估 RTP 式平均抖动 `|D|`，但一次孤立 30 ms 突发正是卡帧的来源，
平均值会把它摊平。这里改为直接测“要吸收的迟到量”：

```
delay = 到达 - 发送时戳                 单向延迟
base  = min(delay)                      最快路径（min 滤波，参考 clock 模块）
spread= (delay - base) 的衰减峰值       要吸收的突发深度
period= 发送间隔 EMA                    插值需要的“下一帧”提前量
target= clamp(gain*spread + period, depth_min, depth_max)
depth = 以限定速率趋近 target           看不见台阶
```

`+period` 不是余量：要在发送时刻 P 插值，P 之后那帧也必须已到，否则每次
迟到都会正好缺一帧。

## 播放平滑与切换

发送时戳经 `base` 映射到本地时间；播放头 = `本地时间 - base - depth`。
每帧按真实时间前进，并向目标位置做 ≤5% 的速率微调，所以 depth 变化不会
表现为画面跳变。缓冲被突发跑过就停在最新帧并记一次 underrun（按“卡顿段”
计数，不按帧刷屏）。`depth == 0` 一律拒绝：那就是“没有缓冲”，正是本模块
要消除的卡顿。

## 实测（60 Hz，30 ms 基线延迟，每 3 s 一次 0.5 s 突发）

| 场景 | 平均深度 | 附加延迟 | 输出抖动(RMS) | 稳态卡顿 |
|---|---|---|---|---|
| 低抖动 固定 15 ms | 15 ms | 11 ms | 0.51 ms | 65 |
| 低抖动 固定 160 ms | 160 ms | 155 ms | 0.001 ms | 0 |
| 低抖动 自适应 | 22 ms | 17 ms | 0.008 ms | **0** |
| 高抖动 固定 15 ms | 15 ms | 12 ms | 2.30 ms | 267 |
| 高抖动 固定 160 ms | 160 ms | 136 ms | 0.011 ms | 0 |
| 高抖动 自适应 | 70 ms | 46 ms | 0.074 ms | **0** |

- 抖动指标：高抖动下自适应 0.074 ms，比固定 15 ms 的 2.30 ms 降 **97%**；
  同时延迟只有固定 160 ms 的约 1/3。
- 额外延迟上界：深度被 `depth_max` 钳死（配置上限），实测峰值从不越界，
  见 `adaptive_extra_latency_bounded`。
- 冷启动：首个突发无法预知，会卡一次；学到之后同型突发全部吸收
  （`adaptive_cold_start_bounded` / `adaptive_absorbs_repeat_bursts`）。

`make test` 会打印 `cmp`（上表）、`curve`（固定深度 × 抖动的延迟/平滑度
曲线）和 `track`（抖动→深度单调关系）行。
