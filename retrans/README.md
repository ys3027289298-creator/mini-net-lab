# retrans

按 tick 的 NACK 补发模块。`make test` 跑自检。

## 机制

- **发送端 `Sender`**：环形缓存窗口保留最近 `win` 个 tick 的原始报文。
  - `sender_send` 编码上线并把同一字节存入窗口；
  - `sender_retrans(tick)` 命中窗口就返回缓存的**原报文字节**（补发内容与首发
    逐字节一致，解码后逐字段一致）；窗口已淘汰或从未发送过返回 `-1`，累计
    `cache_miss` / 记录 `last_miss`，不编造状态。
- **接收端 `Receiver`**：
  - `recv_on_packet` 解码后按 `next` 期望 tick 检测缺口，记录缺失 tick 及其
    检测时刻；已投递或已缓存的重复报文直接丢弃并计 `dups`；
  - 按序报文走快速路径直接投递、不占重排槽位（重排缓冲满时填补报文仍能
    进入）；乱序报文进重排缓冲，缺口补齐后连续排空，按 tick 顺序投递到 `log`；
  - `recv_on_heartbeat(sender_tick)`：心跳通告发送端进度，整段全丢（没有任何
    报文到达可触发检测）和流末尾丢包也能及时发现缺口，不必干等下一个数据包；
  - `recv_missing` 返回当前待 NACK 的缺失 tick（已到达但排在缺口后面的
    pending tick 不会被请求），缺口补齐后自动移出，重复 NACK 天然去重；
  - 每个通过补发/迟到原文补齐的缺口记录一条 `{tick, delay}`，`delay` 是
    检测时刻到补齐时刻的 tick 差——补齐延迟作为数据暴露，不改变任何状态字段；
  - `recv_nack_failed(tick)` 在发送端缓存不够时把缺口登记到 `unrecovered`
    上报列表，`next` 不前进、不伪造该 tick，后续状态继续缓存在它后面。

## 自检场景

1. 无丢包基线；
2. 丢 3 个 tick + 2-tick RTT 补发 + 重复补发 + 迟到原文：补齐结果与基线
   `state_equal` 逐字段一致，补齐延迟、去重计数符合预期；
3. 缓存窗口装不下丢失 tick：报告 `cache_miss` / `unrecovered`，缺口保持
   未补齐而不是假装补齐；
4. 200 组随机丢包模式差分压测：补发报文与首发 `memcmp` 逐字节一致，重组流
   与无丢包结果逐字段一致，覆盖流末尾/全丢段（心跳检测）；
5. 重复报文、坏包、重排缓冲满、零窗口、心跳幂等等边界检查。
