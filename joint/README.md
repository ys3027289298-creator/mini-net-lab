# joint

AOI 裁剪与快照字段压缩的联合发送集合规划。`make test` 跑自检。

## 问题

各自最优时，总带宽被切成两份独立预算：

- AOI 阶段按可见度收实体，按全字段成本扣自己那一份；
- 快照阶段按字段重要度选字段类型，花自己那一份；
- 任一份的剩余预算不能转给另一份，合起来的松弛预算被浪费。

## 联合模型

把两个信号合成一个候选收益，在同一份总带宽（字节）上做一次 0/1 背包：

```
benefit(entity, field) = visibility(entity) * importance(field)
cost(entity, field)    = 该字段编码字节数
```

- 可见度由 AOI 给出：半径外为 0，半径内按距离线性衰减（同 AOI 模块的半径语义）。
- 整数字节预算上跑精确 DP，同值不翻转，结果确定。
- 重要度为 0 的字段不进入候选集，永远不占预算。
- 可见度为 0 的实体不产生候选。

## 空集合策略

规划结果为空时返回状态 0 和原因（预算为 0、预算低于最便宜候选、无正收益候选、无可见实体），
调用方必须**上报空集合并发 0 字节**，不允许回退为全量发送。自检里的
`transmit_bytes()` 模拟该调用方策略。

## 对照基线（分别最优）

`plan_separate` 复现各自为政的做法：预算 50/50 切开，AOI 按可见度贪心收整实体，
快照按重要度对已收实体统一开字段。基线集合对联合背包始终可行，因此联合收益在
任何预算下都不低于它（自检对预算 0..40 做了支配性扫描）。

自检主场景输出联合相对基线的收益比 `gain_ratio` 与提升百分比 `gain_pct`。
