# anchor

关键帧（锚点）发送时刻选择：在「发太密浪费带宽、发太稀恢复慢」之间做自适应权衡。

`make test` 跑自检：策略状态机单元测试、恢复过程仿真、扫描表、等带宽配对比较，
并在当前目录生成 `anchor.csv`（带宽—恢复时间原始数据）与 ASCII 权衡曲线。

## 模型

- 场景：4000 tick 确定性轨迹（xorshift32，固定种子，可复现）。每 180 tick 有
  30 tick 的故障段：丢包率 35%、场景变化幅度同时变大；其余 tick 丢包 2%、变化小。
- 关键帧 120 字节，增量包 12 字节。两种发送策略共用同一条丢包轨迹
  （丢包判定在策略决策之前做），保证对比公平。
- 接收端在已同步时丢包即失步，恢复时间 = 失步到下一个**成功送达**的关键帧的
  tick 数；关键帧本身丢失则等下一个。

## 策略

- 固定间隔 `fixed(interval)`：每隔 interval tick 发一个关键帧；
  interval 为 0 或负数直接拒绝（`fixed_zero_rejected`）。
- 自适应 `adapt(chg_th, loss_th, min_gap, max_gap)`：维护发送端观测丢包的
  EWMA（α=1/16），紧迫度
  `urgency = change/chg_th + loss_ewma/loss_th`，≥1 即发；
  `min_gap` 硬下限防止刷屏，`max_gap` 硬上限防止接收端饿死。
  另外带快速重锚：观测到丢包意味着接收端可能已失步，立即发一个关键帧，
  随后还有 2 次 `min_gap` 间隔的重试预算（关键帧本身也可能丢，预算共 3 个
  关键帧，立即重发即消耗第 1 个），新的丢包会重新武装预算；预算耗尽且
  紧迫度不足时回到正常节奏。

## 输出

- 对固定策略扫 29 个间隔、自适应扫 10 个变化阈值，得到带宽（字节/tick）与
  恢复时间（均值/p50/p90/max）的权衡曲线，写入 `anchor.csv`。
- 等带宽配对：每个自适应点找带宽差 ≤3% 的最近固定点，比较恢复均值，
  自检要求配对 ≥8、自适应胜率 ≥80%、平均改善 ≥15%（`equal_bw_shorter_recovery`）。
