# spectator

观战端稀疏快照的平滑窗口选型。`make test` 跑自检。

## 两条约束

设快照间隔 `Ts`、平滑窗口长 `W`、可接受的明显滞后上界 `Lmax`：

1. **盖住快照间隔（防一顿一顿）**：`W >= Ts`
   窗口至少覆盖一个完整快照间隔，任一时刻窗内都有快照参与平均。
2. **不引入明显滞后**：`W/2 <= Lmax`，即 `W <= 2*Lmax`
   对称窗以当前时刻为中心需要缓存 `W/2` 的数据，滞后就是半个窗长。

交集即可用区间：

```
Ts <= W <= 2*Lmax
```

程序取 `Ts = 0.10s`（10 Hz 快照）、`Lmax = 0.10s`，区间为 `[0.10, 0.20] s`。
若 `Ts > 2*Lmax` 区间为空，只能提高快照频率，没有窗口能同时满足两条。

## 窗口怎么选

每段操作先从快照序列的过零点估计主频 `fest`，再取

```
W = max(Ts, kappa/fest),  kappa = 0.25
```

即估计周期的四分之一，但不允许短于一个快照间隔（约束 1 的钳位）。

## 指标

- `jitter`：扣除已知 `W/2` 滞后后，观战轨迹与本机真值的偏差 RMS，按信号幅度归一化，越小越跟手；
- `lag`：单位阶跃经对称窗、按实时取景（窗心只能停在 `T - W/2`）后输出过 0.5 的墙钟时刻，即相对本机的实际滞后。

## 三段录制（三组九个数）

| 操作 | 真值主频 | `fest` (Hz) | `W` (s) | jitter | lag (s) |
|---|---|---|---|---|---|
| 缓慢转身 turn | 1.5 | 1.375 | 0.182 | 0.576 | 0.095 |
| 中速挥砍 swing | 4.0 | 3.875 | 0.100 | 0.863 | 0.055 |
| 快速连招 combo | 9.0 | 1.000（混叠） | 0.250 | 0.960 | 0.125 |

快速连招 9 Hz 超过 10 Hz 快照的奈奎斯特频率 5 Hz，主频被混叠低读成 1 Hz，
窗口被迫取到 0.25 s，lag = 0.125 s 超过 `Lmax`（同时 `W` 也越过区间上界 0.20 s）。
触发条件诊断：三段 `fest` 与 `Ts`、奈奎斯特频率并列打印。

修复验证：快照提到 20 Hz（`Ts = 0.05s`）后 `fest` 恢复为 8.875 Hz，
`W` 缩回 0.05 s、lag 降到 0.025 s，回到区间内。
