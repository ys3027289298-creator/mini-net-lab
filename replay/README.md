# replay

确定性回放：同一段输入重放任意次，逐位一致。固定浮点求和顺序、按帧记录输入与
状态哈希、差异定位到帧与字段、哈希碰撞概率可算、回放窗口不足要报告。

`make test` 跑自检。

## 为什么两次回放会不一致

实体受力是「对本帧每个同伴贡献求和」。浮点加法不满足结合律，按存储顺序累加时，
结果取决于实体的分配/生成顺序——同一段输入、同一份快照，两次进程里数组排布
不同，求和顺序就不同，末位比特随之漂移，随后被积分放大成明显的分歧。

本模块把求和顺序钉死为 **按实体 id 升序**（`world_step` 里先 `sort_ids` 再累加），
积分阶段逐实体进行、不共享累加器，因此与存储顺序无关。自检把同一世界的 6 个实体
按全部 `6! = 720` 种存储顺序各跑 128 帧：规范模式下逐帧逐字节零差异；作为对照，
按存储顺序求和的模式有 704/720 种会分歧——正是上面描述的问题。

## 确定性规则

| 规则 | 保证 |
|---|---|
| 归约顺序 | 所有对实体的求和按 id 升序，不看存储顺序 |
| 两阶段更新 | 先算完所有实体的力，再统一积分；更新不读半新半旧的状态 |
| RNG | 每步恰好推进一次，且在任何输入分支之前 |
| 输入记录 | 存原始 IEEE-754 位模式，不存十进制文本，解析不会引入舍入 |
| 状态比较 | 逐位比较，不用 `==`：`+0.0` 与 `-0.0`、不同的 NaN payload 都算不同 |
| 编译 | `-ffp-contract=off`（禁止 FMA），源码 `#error` 拒绝 `-ffast-math` |

跨构建自检：gcc / clang × `-O0/-O1/-O2/-O3/-Os` 共 10 个构建跑同一录制，
末帧 128 位状态哈希全部相同（`cross_build_final_hash_lo/hi` 输出一行可直接 `diff`）。
`-ffast-math` 构建在编译期被拒绝。

## 录制格式

小端、定长记录，体积随时长严格线性：

```
header 48B : magic, version, flags, frame_count, spawn_count, seed,
             serialized_bytes, reserved, initial_state_hash(128b)
spawns     : 16B/个 { id, x bits, y bits, hp }
per frame  : 276B { frame, tick, input(buttons/ax/ay), state_hash(128b),
                    canonical_state(236B) }
```

`体积 = 48 + 16 × spawn_count + 276 × frame_count`。

## 校验与定位

`verify()` 从 seed 和 spawn 表重建世界，逐帧喂回输入的 **位模式**，每帧做三件事：

1. **哈希过滤**：重放状态哈希 vs 录制哈希；
2. **逐位比对**：重放规范化字节 vs 录制快照字节（判定的真相来源）；
3. **完整性**：录制字节重新哈希 vs 录制哈希（发现录制被原地改写）。

三者任一不符即定位到 **首个** 分歧帧，并给出字段名与两侧原始位（`ent[2].vy` 级别）。
多处篡改只报最早一处；同帧多字段差异按 `id/alive/x/y/vx/vy/hp` 顺序报第一个。

自检覆盖：

- `verify_match`、`hash_diffs_zero`、`bit_diffs_zero`、`hash_bitwise_agree`
  —— 哈希判定与逐位判定零分歧；
- 输入篡改定位到帧 17、状态篡改定位到帧 29（字段 `ent[1].x`）、多处篡改只报帧 11；
- 只改录制哈希不改字节 → 定位到帧 33，字段 `record_hash`；
- 截断、magic/version 错误、非规范标志、帧数越界 → 拒绝并给出错误字段。

## 哈希碰撞概率

状态哈希是 **128 位**（两个独立的 64 位累加器，反向遍历字段、不同初值）。
按均匀哈希模型：

| 量 | 值 |
|---|---|
| 单对状态碰撞概率 | `2^-128 ≈ 2.9e-39` |
| 一次 192 帧录制的并集上界 `N/2^128` | `≈ 5.6e-37` |
| 192 帧全体的生日界 `N(N-1)/2 / 2^128` | `≈ 5.4e-35` |

单字段定位不依赖哈希，由逐位快照比对完成，因此不存在「字段哈希碰撞掩盖差异」
这一路径。

**关键点**：上面的数字只是**过滤器**的误报率。哈希判定为「相等」的帧仍会做逐位
比较并以其为准，所以哈希碰撞最多让某帧漏过过滤、退化为逐位比较，**不会**把不同的
状态判成一致。自检里 `collision_guard_*` 用「哈希故意与重放一致、但字节被改」构造
出碰撞的可见效果：`hash_diffs=0` 而 `bit_diffs=1`，定位仍然正确。

## 回放窗口

`History` 是保留最近 `WIN_CAP = 8` 帧快照的环形缓冲。`history_get` 的返回：

| 情况 | 返回值 | 计数 |
|---|---|---|
| 帧在窗口内 | `REPLAY_OK` | — |
| 帧比窗口最旧还旧 | `REPLAY_WINDOW_SHORT` | `window_short++` |
| 帧比最新还新 | `REPLAY_WINDOW_FUTURE` | 不计入 `window_short` |

`history_rewind` 回到窗口内某一帧会重跑到最新保留帧，要求每个快照逐位复现
（`window_rewind_bitwise`）；窗口不足时**报告并保持现场状态不变**
（`window_rewind_short_leaves_live`），不静默丢弃、不改动本地状态。
